# ── 為什麼是每分鐘，而不是固定 :01 / :31 ──
#   tick 每分鐘做一條判定，不成立就什麼都不做、不印任何東西
#   （所以 log 不會被灌爆）：
#     ① floor(有效now,30min) > 已拉到的 slot  → Job A′ 搬當下這一格
#   好處是機器睡著／斷網／PG 沒起來的那幾輪，醒來後「下一分鐘」就補上 ——
#   cron 不會替你補跑錯過的排程，固定半點就得乾等到下一個半點。
#   ★ 中間漏掉的格子會一併補齊 —— 資料都在 baseline_grid，
#     Job A′ 一次 INSERT..SELECT 就搬完。
#
# ★★ 2026-09-04：TDX 拉取邏輯全部移除（Job A / Job C / sync_stations）。
#   唯一的資料來源是 baseline_grid，tick 只在 demo 回放模式下有事做 ——
#   非 demo 時它印一次警告就離開。出處：
#   meet/20260904/計劃-移除TDX拉取邏輯.md
#   ⚠ 本檔改過就要重裝 crontab（見上面「安裝」），否則 cron 還在跑舊的
#     sync_stations —— 那支檔案已經不存在，每天會多一次 ModuleNotFoundError。
#
# ── macOS 三個會讓 cron「安靜地什麼都沒做」的坑 ──
#   1. cron 的 PATH 只有 /usr/bin:/bin —— 所以一律走 run_job.sh，
#      不要在這裡直接寫 uv（run_job.sh 用 uv 絕對路徑）
#   2. 睡眠中不會補跑。筆電闔上 = 那幾輪就是沒有，level30 直接缺格。
#      要連續資料就別讓機器睡（caffeinate -s，或系統設定關閉自動睡眠）
#   3. 存取 /Volumes 下的外接磁碟可能被隱私權限擋。若 log 完全沒產生，
#      到「系統設定 → 隱私權與安全性 → 完全取得磁碟存取權」加入 /usr/sbin/cron
#
# ── 另外兩個前提 ──
#   * PostgreSQL 容器要在跑（podman ps 看 youbike-pg），否則每輪都 failed
#   * Job B 會打 SageMaker endpoint，endpoint 沒開時 Job B 記 failed
#     （Job A′ 仍會 success —— 兩件事各記一列，這是刻意的）
#
# ════════════════════════════════════════════════════════════
# 實際內容（以下一行貼進 crontab -e）

#   cron 找不到檔案時**完全不出聲**，看起來就像「裝了但什麼都沒發生」。

#           uv run python -m jobs.demo --status      # 回放時鐘與進度
