# ⚠⚠ 如果你之前裝過舊的 crontab，**現在就要移除**：
#
#       crontab -l          # 先看裝了什麼
#       crontab -r          # 整份移除（目前只有 tick 那一行，可直接清掉）
#
#   不移除的下場：cron 每分鐘去跑一支不存在的 jobs.tick，每分鐘一次
#   ModuleNotFoundError。更糟的情況是 code 還沒更新的機器上舊 tick 仍能跑，
#   於是 cron 與 demo --run **同時推進虛擬時鐘** —— job_run 同一個 slot
#   兩列、endpoint 被打兩次，而且不會有任何錯誤訊息。
#   （demo --run 的 DB 租約擋得住第二個 --run，擋不住舊版的 tick。）
#
# ── 為什麼改成常駐迴圈 ──
#   cron 的最小粒度是 1 分鐘。×30 快轉下 1 分鐘真實 = 30 分鐘虛擬，一輪就
#   跨過一整格，「這一格有沒有預測 → 要不要降速」的逐格判定當場失效。
#   常駐迴圈睡「距下一格的真實時間」但不超過 2 秒，兩種速度都不漏格。
#
# ── run_job.sh 還留著 ──
#   手動補跑單一 job 仍然走它（有鎖、有 log）：
#       bash jobs/run_job.sh batch_predict --slot '2026-05-01 08:00'
#       bash jobs/run_job.sh dispatch_sweep
#   ⚠ 不要用它跑 demo --run —— 那是常駐前景進程，run_job.sh 的 log 收集
#     是「跑完才寫檔」，常駐進程等於永遠不寫。
