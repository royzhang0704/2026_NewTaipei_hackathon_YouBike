# 命題背景與系統架構

## 賽事與命題

- 賽事：2026 新北市 AI 智慧城市黑客松（DIGITIMES 主辦）
- 組別：交通局 —— YouBike 智慧調度
- 命題：「新北市公共自行車營運調度數據視覺化及預測模型」
- 資料集：新北市資料開放平台 — YouBike2.0 租賃站歷史數據（6 個月）
- 技術限制：生成式／預測模型僅限 Amazon Bedrock、SageMaker AI，不可用外部 API
- 規模：新北市 YouBike2.0 站點約 1,538 站

## 命題痛點 → 本專案作法

| 痛點 | 作法 |
|---|---|
| ① 尖峰時段「無車可借／無位可還」 | 風險門檻 `T = max(2, 15% × 車柱)`，空站與滿站雙邊判定 |
| ② 現行系統只有即時資料、無法預測 | SageMaker DeepAR，H=6（未來 3 小時、每 30 分一格），每半小時全站批次預測 |
| ③ 無警示通知機關的功能 | 時間制四級風險燈號 + 具體調度動作（補車／取車 N 台、由哪一格起算） |

## 系統架構

```
歷史真相 baseline_grid ─► Job A′（tick）─► 30 分水位歷程
                                              │
                                              ▼
                                     Job B batch_predict ─► SageMaker Endpoint（DeepAR H=6）
                                              │
                                              ▼
                              forecast_history（q19 / q50 / q90）＋ risk_snapshot（風險判定）
                                              │
        前端 ◄── FastAPI 查詢端點（只讀 DB，毫秒級，不打 SageMaker）◄──┘
```

**核心設計決定：查詢端與推論端分離。**

- Job B 每 30 分鐘把全站預測 + 風險判定寫進資料庫。
- 前端查詢（供需概況、主動警示、單站檢視）只讀資料庫，不觸發即時推論。
- `POST /predict` 的即時推論保留給 what-if 與交叉驗證，頁面不使用。

## 模型

- DeepAR，訓練集 2025-08-01 ~ 2026-03-31（回放 2026-05 時模型沒見過答案）。
- H = 6（3 小時）、context = 48（過去 24 小時）、頻率 30 分。
- 測試 WQL ≈ 0.197、RMSE ≈ 4.52（2026-04 整月 119 個原點）。
- 已知限制：q=0.19 是 H=4 校準值，H=6 逐格分位數尚未校準，預測愈遠下界愈鬆，空站會被系統性低估。

## 前端畫面

- **供需概況**：四格 KPI（已空站或滿站／預測 1 小時內／空站／滿站），可點篩選主動警示清單。
- **主動警示**：全市／同區風險清單，方向（空站／滿站）與時機兩軸篩選。
- **空滿熱度圖**：地圖上每站一點，暖色 = 空站傾向、冷色圈 = 滿站傾向、脈動 = 需立即處理。
- **單站檢視**：24 小時水位（實況 + 3 小時預測）、風險卡、調度動作。
- **調度助理**：本對話介面。即時狀態由系統直接查資料庫回答；名詞、規則、SOP 由本知識庫回答。
