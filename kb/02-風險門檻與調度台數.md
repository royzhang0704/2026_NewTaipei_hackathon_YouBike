# 風險門檻與調度台數 —— 設計依據

## 風險門檻 T 為什麼是「15% × 車柱，下限 2，不封頂」

門檻公式：`T = clamp(round(0.15 × 車柱), 2, ∞)`

依 2026-04 全月、201 萬格實測校準。設計時排除過的其他做法：

- **不用純比例 20%**：實測會標紅 31.4% 的格子 —— 警報疲勞、沒有資訊量。
- **不用純絕對值 ≤ 2**：對 99 柱大站太鬆。滿站集中在小站（命中站容量中位數 15，全市中位數 25）。
- 早期版本用 10% + 封頂 5，是開發者自己挑的；8/31 使用者定案改成 **15% / 不封頂**，空站觸發率 20.1% → 24.5%，對大站更敏感（99 柱站 T = 15）。

這組參數的實測觸發率：空站 20.1%／滿站 2.4%／任一 22.5%（10% 封頂 5 那版的數字；改 15% 後空站升到約 24.5%）。

## 越線一律看 q50，不看 q19

- 用下界 q19 判定太敏感，空站觸發率會飆到 26%。
- 用 q50（最可能路徑）判定，還有一個數學上的好處：同一格不可能「同時空站又滿站」（q50 不能同時 ≤ T 又 ≥ cap−T，除非 cap ≤ 2T，最小站 8 柱 > 4）。
- 三個分位數（q19/q50/q90）降級成「信心註記」：連 q90 都越線 = 運氣好也缺 = 幾乎確定（`almost_certain`）；q50 越線 = `likely`；只有 q19 越線 = `possible`。

## 調度台數：目標是「回到常態水位」，不是「剛好脫離紅區」

8/31 使用者定案。

**台數 = 下面兩個缺口取大的**（`basis = "slot_average"`）：

| 缺口 | 算法 |
|---|---|
| 現況缺口 | 該時刻歷史同時段平均 − 現在實測可借量 |
| 窗內缺口 | 預測窗逐格「歷史平均 − q50」的平均 |

- 補車 = `ceil(歷史平均 − 窗尾 q50)` 方向；取車對稱。
- 目標值是這站這個時段的**常態水位**（介面顯示「常態約 N 台」）。

### 為什麼比「窗尾」而不是「最嚴重那一格」

模型已經把自然消退算進去了。調度只該搬「三小時後仍然不會自己消退的那部分」。實測 origin 17:00、取車 12 站：

- 舊算法 20 台
- 比最嚴重格 → 113 台（大幅超搬）
- 比窗尾 → 49 台
- 其中 3 站算出 0 台（尖峰卡住但會自行退燒，派車是白跑）

### 為什麼窗內取「平均」而不是只看窗尾

窗尾單格會被 origin 對齊的偶然綁架（某站窗尾差 0.11 台就從「補 6 台」翻成「不派車」）。取平均後，會自己消退的格差距本來就趨近 0，不影響「只搬消退不掉的部分」。

### 為什麼台數要含「現況缺口」

高風險的判定條件是**實測**已越線，但如果台數只看預測，會出現「現在 0 台卻說不用派車」。所以台數要 `max(窗內缺口, 現況缺口)`。

### 退路（basis = "threshold"）

查無歷史同時段平均、或樣本數不足（< 10 筆）時，退回門檻算法：補／取到「安全範圍」= `門檻 − 路徑極值 + 1`。

### hold（暫不派車）

兩個缺口都 ≤ 0 = 現在沒事、預測掉下去也只是這站的正常作息 → 建議 hold。但 **level = 高風險一律不准 hold**：高風險的定義就是現況已越線、人現在就借不到車，不可能得到「不用去」的結論，此時改走安全範圍。

hold 不影響風險燈號 —— 尖峰卡人的事實仍由等級與 onset 誠實呈現。

## 風險燈號 vs 調度台數：兩件事

- **風險燈號**看窗內最嚴重的一格 —— 卡人的事實不會被抹掉。
- **調度台數**看窗尾／常態水位 —— 只搬消退不掉的部分。

所以會出現「高風險，但建議暫不派車」這種組合，是設計如此。
